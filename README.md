# ProjectAndroidITunes

Android-приложение на Kotlin и Jetpack Compose для практики «Работа с сетью».

## Возможности

- Поиск музыки по названию трека или исполнителю, до 25 результатов.
- Список с обложкой, названием, исполнителем и альбомом.
- Карточка трека: отдельная загрузка по ID, альбом, жанр, дата выхода, длительность, цена и ссылка в iTunes.
- Состояния начала поиска, загрузки, пустого результата и ошибки; повтор неудачного запроса.
- Возврат из карточки сохраняет список и позицию прокрутки. ViewModel сохраняется при повороте экрана.

## Архитектура

`presentation → domain ← data`

- `domain`: Track, TrackRepository, SearchTracksUseCase, GetTrackUseCase, типы ошибок. Нет зависимостей на Android и Retrofit.
- `data/remote`: ITunesApi, DTO и преобразование DTO в Track.
- `data`: ITunesTrackRepository, обработка HTTP, таймаутов, сетевых ошибок и некорректных ответов.
- `presentation`: MusicViewModel, StateFlow состояния экрана и Compose UI. Запросы запускаются через viewModelScope, отмена корутин не становится ошибкой интерфейса.
- `di`: AppContainer связывает Retrofit/OkHttp, репозиторий и use case'ы; создаётся один раз в Application.

Retrofit 3.0.0 использует асинхронные suspend-запросы. Репозиторий выполняется на Dispatchers.IO. Интерфейс подписывается на состояние через collectAsStateWithLifecycle.

## API

Базовый адрес: `https://itunes.apple.com/`

- `GET search?term=<введённый текст>&media=music&entity=song&limit=25&country=US`
- `GET lookup?id=<trackId>&country=US`

Retrofit кодирует query-параметры. API не требует ключа. Поиск запускается только по кнопке/клавише поиска, чтобы не расходовать лимит на каждую букву. HTTP 429 отображается отдельным сообщением. Встроенного кэша ответов и бонусного задания нет.

Документация: https://performance-partners.apple.com/search-api

## Проверка

Открыть папку `android` в Android Studio, синхронизировать Gradle и запустить конфигурацию `app` на устройстве с API 24 или выше.

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Тесты используют MockWebServer и тестовый диспетчер корутин. Проверяются реальные Retrofit-запросы, кодирование параметров, преобразование ответа, пустые результаты, ошибки HTTP/сети/таймаута/JSON, отмена, повтор запроса и переход к деталям.

## Сценарий для записи сдачи

1. Запустить приложение с интернетом. Ввести `Daft Punk` и нажать «Найти». Показать индикатор загрузки и список.
2. Нажать на трек, показать загрузку и карточку, вернуться назад.
3. Отключить Wi-Fi и мобильную сеть устройства/эмулятора. Выполнить новый поиск. Дождаться сообщения об ошибке (таймаут запроса ограничен 20 секундами).
4. Включить интернет, нажать «Повторить», показать восстановление списка.
5. Для ошибки карточки: из загруженного списка отключить интернет и открыть трек; затем включить интернет и повторить.
6. Для скриншота запросов открыть в Android Studio `View → Tool Windows → App Inspection → Network Inspector`, выбрать процесс `com.example.projectandroiditunes` на устройстве API 26+ и выполнить поиск/открыть карточку. На скриншоте показать GET `/search` или `/lookup`, параметры, статус и ответ. Сетевой клиент OkHttp поддерживается Network Inspector.

Запись экрана и скриншот сетевого инспектора нужно снять на запущенном устройстве; они не генерируются unit-тестами. Git-операции в рамках реализации не выполняются.
## Результаты проверки реализации

- Debug APK собран (`assembleDebug`).
- Android Lint: 0 ошибок; предупреждения включают обновления зависимостей и ресурсы исходного шаблона.
- 13 JVM-тестов прошли через прямой запуск JUnitCore (12 новых и 1 тест шаблона).
- Реальные `/search` и `/lookup` проверены с компьютера через Java HTTPS: HTTP 200.
- В среде Codex штатная задача `testDebugUnitTest` не смогла загрузить классы из пути с кириллицей через Java argument file. Для проверки скомпилированных тестов classpath был передан напрямую в JUnitCore. Постоянные настройки кодировки проекта не менялись.
- Запуск на устройстве, запись экрана и скриншот Network Inspector в этой среде не выполнены: ADB не удалось инициализировать свой каталог настроек. Сценарий ручной проверки приведён выше.
